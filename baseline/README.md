# 文档填表任务 — 规则/正则基线实验

## 概述

本目录实现三个文档填表场景的**朴素规则基线**，刻意采用"不考虑格式特殊性"的方案，
以展示规则方法的固有上限，为后续大模型方案提供对比下界。

---

## 运行方式

```bash
# 1. 进入仓库根目录
cd DocFlow

# 2. 安装依赖（如未安装）
pip install openpyxl python-docx

# 3. 运行全部三个实验
python baseline/run_baseline.py
```

运行完成后，结果文件保存在 `baseline/output/` 目录下。

## 三个实验说明

### 实验一：TXT → 结构化填表（正则基线）

| 项目 | 路径 |
|------|------|
| **输入** | `测试集/txt/合肥市2024年国民经济和社会发展统计公报.txt` |
| **输出** | `baseline/output/exp1_result.json` |

**任务**：从统计公报纯文本中抽取 6 个经济指标，填入结构化表格。

**基线方法**：为每个字段编写一条单行正则表达式，在全文中搜索首次匹配。

**刻意设计的失败点**：

| 字段 | 失败原因 | 原文片段（示意） |
|------|----------|-----------------|
| GDP总量 | 脚注 `[2]` 打断数字紧跟 GDP 的模式 | `GDP）[2]13507.69亿元` |
| 城镇化率 | 关键词与数值跨行，`[\d.]` 无法匹配 `\n` | `城镇化率\n86.38%` |
| 人均GDP | "人均"与"GDP"之间有换行符 | `人均\nGDP136063 元` |

**预期指标**：

| 指标 | 预期值 |
|------|--------|
| 字段命中率 | 50%（3/6） |
| 字段准确率 | 50%（3/6） |
| E2E 准确率 | 0% |

### 实验二：DOCX → XLSX（单位关键词匹配基线）

| 项目 | 路径 |
|------|------|
| **输入** | `测试集/包含模板文件/2025年中国城市经济百强全景报告/2025年中国城市经济百强全景报告.docx` |
| **模板** | 同目录 `2025年中国城市经济百强全景报告-模板.xlsx` |
| **输出（填表结果）** | `baseline/output/exp2_filled.xlsx` |
| **输出（评估报告）** | `baseline/output/exp2_result.json` |

**任务**：从 Word 报告的散文段落中，提取 10 个城市各 4 项指标，填入 Excel 模板。

**基线方法**：在城市名开头的段落中，用 `([\d.]+)\s*亿元` / `([\d.]+)\s*万` / `([\d.]+)\s*元` 等按"单位"顺序提取首个匹配数字。

**刻意设计的失败点**：

原文数字使用**千位逗号分隔**（如 `56,708.71 亿元`），正则 `[\d.]+` 在遇到逗号时停止，只捕获逗号后片段（`708.71`），导致数值系统性偏低。

示例：
```
原文:  上海以 56,708.71 亿元的 GDP 总量 ...
提取:  708.71   ← 错误，应为 56708.71
```

**预期指标**：

| 指标 | 预期值 |
|------|--------|
| 字段命中率 | 100%（字段均被提取，但值错误） |
| 字段准确率 | ~2.5%（仅1个无逗号字段偶然正确） |
| 城市 E2E 准确率 | 0% |

### 实验三：XLSX → DOCX（精确字符串匹配基线）

| 项目 | 路径 |
|------|------|
| **数据** | `测试集/包含模板文件/2025山东省环境空气质量监测数据信息/山东省环境空气质量监测数据信息202512171921_0.xlsx` |
| **需求文件** | 同目录 `用户要求.txt` |
| **模板** | 同目录 `2025山东省环境空气质量监测数据信息-模板.docx` |
| **输出（填表结果）** | `baseline/output/exp3_filled.docx` |
| **输出（评估报告）** | `baseline/output/exp3_result.json` |

**任务**：根据用户需求（自然语言），将 xlsx 中的空气质量数据按指定城市和时间，
分别填入 Word 模板的三张子表。

**基线方法**：从需求文本中提取城市名后，用 **Python 默认 Unicode 排序**代替对
"表一/表二/表三 → 城市"映射关系的语义解析，按排序结果分配城市。

**刻意设计的失败点**：

正确映射（用户需求）| 基线映射（Unicode 排序）
---|---
表0 → 德州市 | 表0 → **临沂市** ✗
表1 → 潍坊市 | 表1 → **德州市** ✗
表2 → 临沂市 | 表2 → **潍坊市** ✗

因为 `ord('临')=20020 < ord('德')=24503 < ord('潍')=28156`，Unicode 排序结果与
用户意图完全相反。无法通过规则解析"表一""表二""表三"这类自然语言表示。

**预期指标**：

| 指标 | 预期值 |
|------|--------|
| 表分配准确率 | 0%（3张表全部城市错位） |
| 单元格准确率 | ~18%（部分共有字段偶然匹配） |
| 行填充率 | ~94%（行数量接近但城市错位） |

## 评估指标说明

| 指标 | 含义 |
|------|------|
| **字段命中率 (Field Hit Rate)** | 成功提取出来的字段数 / 模板总字段数 |
| **字段准确率 (Field Accuracy)** | 提取值与标准答案一致的字段数 / 模板总字段数 |
| **E2E 准确率 (E2E Accuracy)** | 全部字段均正确的记录数 / 总记录数 |
| **表分配准确率 (Table Assignment Acc)** | 城市与表格对应关系正确的表数 / 总表数 |
| **单元格准确率 (Cell Accuracy)** | 值与标准答案一致的单元格数 / 总单元格数 |
| **行填充率 (Row Fill Rate)** | 实际填写行数 / 应填写行数 |
